# 个人 TickTick APK · 问题定义

> 为唯一使用者提供一款长期自用、视觉接近指定滴答清单截图、数据联网保存且无需登录的 Android 任务应用。

<!-- 初稿日期: 2026-10-02 ｜ 相关: persona.md · scenarios.md · prd.md -->

## 问题陈述

使用者希望在荣耀 200（Android 15 / MagicOS 9.0）上长期管理当天、逾期、未来和重复任务。现有目标不是复制滴答清单全部能力，而是保留最常用的任务闭环，并把指定历史版本截图中的深色界面尽量像素级还原。

## 动机与价值

- 一眼分清仍需处理的任务、已完成任务和过期任务。
- 用一句自然语言快速创建任务，同时保留手动纠错能力。
- 准点提醒，避免任务被遗忘。
- 用今天、周、月三个尺度查看任务，包括无具体时间和跨天任务。
- 数据保存在联网数据库，应用无登录流程，适合单人使用。

## 当前替代方案

### 正式方案

滴答清单具备完整能力，但本项目只需要其中一小部分，并要求复刻用户提供截图对应的视觉与交互。

### 土办法

直接使用系统提醒或零散记录，无法统一处理逾期、重复实例、跨天显示与历史完成状态。

### 忍着不解决

继续使用功能过多或界面版本不同的现成应用，会牺牲目标视觉和精简操作路径。

## 市场洞察

滴答清单官方资料验证了智能日期识别、周/月日历、重复实例与提醒等交互语义。指定截图仍是本项目视觉真值；当前官方界面只作为行为参考。

## 约束条件

- 唯一使用者，个人长期使用，不公开发布。
- 目标设备为荣耀 200、Android 15、MagicOS 9.0。
- 数据必须联网存储；无账号、无登录、无跨设备同步。
- App 不配置访问密钥；服务接口按单人私用前提设计。
- 不做任务详情页、优先级、清单分类、协作、习惯、番茄和第三方日历。
- 视觉以 `ticktick-1.jpg`、`ticktick-2.jpg` 为基线。

## 假设清单

### ✓ 已验证

- 唯一使用者及目标设备已确认。
- 今天、已过期、周、月、创建/编辑、完成/恢复、删除、提醒、重复和搜索均在范围内。
- 周视图采用七天大格子，一屏铺满，不做时间轴样式。
- 跨天任务在覆盖日期每天显示，结束日结束后才过期。

### ⚠️ 合理假设

- 网络不可用时保留待同步修改，恢复网络后自动提交，避免任务操作丢失。
- 像素级验收先以 1200×2664 参考截图等比例比较，再在荣耀 200 真机微调。

### ❓ 待验证

- MagicOS 9.0 上精确提醒的实际偏差及后台权限路径。
- 目标服务器最终允许部署的独立路径、端口和数据库位置。

## 决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 创建/编辑 | 半屏底部弹层 | 字段易发现且保持上下文 |
| 周视图 | 七个大格子铺满一屏 | 一屏浏览完整一周 |
| 月视图 | 复刻截图的紧凑月历 + 两列日卡 | 满足视觉目标 |
| 搜索 | 名称模糊匹配 + 拼音首字母 | 适合中文个人任务 |
