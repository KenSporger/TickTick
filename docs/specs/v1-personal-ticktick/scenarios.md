# 场景需求：个人 TickTick APK

<!-- 初稿日期: 2026-10-02 -->

## 场景 1：一句话创建任务

- **对应 Persona**：唯一使用者
- **触发情境**：想到明天或未来要做的事情。

**叙事**：用户从今天、周或月页面点击加号，在半屏弹层输入“明天下午三点健身”。应用高亮并展示识别出的“明天 15:00”，用户可以直接保存，也可以删除识别结果或手动覆盖日期、时间与提醒。

- **期望结果**：最少步骤创建，解析结果始终可见且可修改。
- **边界 / 异常**：无法可靠识别时只保存标题，不暗中猜测日期。

## 场景 2：创建无时间或跨天任务

- **对应 Persona**：唯一使用者
- **触发情境**：任务只有日期，或持续两天以上。

**叙事**：用户可创建“明天交材料”而不设置具体时间，也可在日期面板选择开始日和结束日创建跨天任务。跨天任务在覆盖的每一天显示为同一个任务。

- **期望结果**：无时间任务不自动提醒；跨天任务直到结束日结束后仍未完成才过期。
- **边界 / 异常**：结束日期不能早于开始日期。

## 场景 3：处理逾期与当天任务

- **对应 Persona**：唯一使用者
- **触发情境**：打开应用检查今天需要做什么。

**叙事**：用户在“已过期”和“今天”之间切换。未完成的逾期任务仍高亮，仅日期或时间标红；完成任务后从逾期列表移出。今天完成的任务留在当天底部并置灰，可以恢复。

- **期望结果**：未完成、已完成和逾期不会因相似的灰色样式混淆。
- **边界 / 异常**：当日具体时间经过不提前进入逾期，次日才过期。

## 场景 4：重复任务推进

- **对应 Persona**：唯一使用者
- **触发情境**：创建每天、工作日、每周或每月重复的任务。

**叙事**：用户设置重复规则和次数。系统只允许操作当前实例，未来周期在日历中只读预览。完成或跳过当前实例后生成下一实例并安排提醒。

- **期望结果**：编辑和删除时明确选择“仅本次”或“本次及以后”，历史记录保持不变。
- **边界 / 异常**：每月目标日期不存在时使用当月最后一天；跳过消耗一次次数。

## 场景 5：按周和月浏览

- **对应 Persona**：唯一使用者
- **触发情境**：规划本周或查看一个月前后的任务。

**叙事**：周视图用七个大格子铺满一屏；周一至周六两列三行，周日占底部整行。月视图保持截图中的紧凑月历与两列日卡。任务太多时显示“还有 N 项”。

- **期望结果**：无需进入复杂详情即可比较每天负担。
- **边界 / 异常**：未来重复投影不能直接完成或编辑。

## 场景 6：模糊搜索任务

- **对应 Persona**：唯一使用者
- **触发情境**：需要找回标题记不完整的历史或未来任务。

**叙事**：用户点击底部搜索入口，输入中文连续或非连续字符、英文或拼音首字母。结果实时更新，未完成优先，完成项置灰，过期日期标红。

- **期望结果**：点击结果直接打开半屏编辑弹层。
- **边界 / 异常**：不做错别字纠正；空输入显示最近编辑任务。

## 场景 7：网络暂时不可用

- **对应 Persona**：唯一使用者
- **触发情境**：任务操作时网络中断。

**叙事**：应用保留用户的创建、编辑或状态变化，并显示等待同步状态；网络恢复后自动提交并刷新服务端数据。

- **期望结果**：操作不丢失，用户能看出尚未同步。
- **边界 / 异常**：同一设备上的后续修改按最后一次本地操作提交。
