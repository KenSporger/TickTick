# 滴答清单任务生命周期：官方资料专项调研

- 日期：2026-10-02
- 模式：Research L2，W4 最佳实践专项刷新
- 目标：只依据滴答清单 / TickTick 官方资料与用户截图，确认“今天 / 已过期 / 月视图、完成、恢复、编辑、删除、重复、提醒”的可观察生命周期
- 产品场景：个人长期使用；Android 15 / MagicOS 9.0 / 荣耀 200；数据联网存储；目标页面像素级复刻
- 证据标签：**【官方已验证】**、**【截图已验证】**、**【待产品决策】**

> 结论先行：官方资料能确认智能清单的日期筛选、日历已完成过滤、重复周期的“前序门闩”、完成后创建下一周期、跳过当前周期、单周期修改/删除，以及提醒入口与 Android 后台限制。官方资料没有公开普通任务完成后在“今天”页的默认驻留时长、取消完成后的精确排序位置、删除系列的弹窗选项与作用范围、闹钟在完成/删除/重启时的底层调度方式。后者必须作为本项目规则明确决策，不能声称是 1:1 已验证行为。

## 1. SCOPE：范围与判定标准

### 1.1 本次要回答的问题

1. 单次任务何时进入“今天”“已过期”和月视图，编辑时间后如何移动。
2. 完成、取消完成（恢复）、删除后，各视图如何显示或隐藏。
3. 重复任务何时产生下一周期，未来周期是否预生成、是否可操作。
4. 每天、工作日、每周指定星期、每月指定日期、指定次数的边界。
5. 完成当前实例、跳过当前周期、删除单周期、删除整个系列是否等价。
6. 提醒在创建、编辑、完成、删除、生成下一周期、设备重启时如何变化。

### 1.2 “最佳实践”判定权重

| 权重 | 标准 | 本报告的用法 |
|---:|---|---|
| 50% | 官方可追溯性 | 官网帮助、官方更新日志、官方应用商店说明优先 |
| 30% | 生命周期无歧义 | 能说明触发条件、状态变化与结果 |
| 20% | 对目标设备可迁移 | Android 15 / MagicOS 9.0 下能形成稳定实现规则 |

### 1.3 证据边界

- 只使用 `help.dida365.com`、`help.ticktick.com`、`dida365.com` / `ticktick.com` 官方页面，以及用户提供的两张截图。
- 中英文帮助相互印证；英文页面若存在疑似翻译错误，以语义更完整的中文官方页为准。
- 官方没有写出的动作后果一律标 **【待产品决策】**，不以社区经验或常规实现补齐。
- 截图只证明静态可见状态，不证明手势、默认过滤或数据库语义。

## 2. SURVEY：官方证据盘点

### 2.1 日期智能清单与日历

- **【官方已验证】** “今天 / 明天 / 最近 7 天”属于按条件筛选任务的智能清单；官方英文帮助明确：“Today”显示到期日期为今天的任务。[Manage Tasks with Lists](https://help.ticktick.com/articles/7055782283059396608)
- **【官方已验证】** 官方 GTD 指南把“今天”描述为每天查看“今天要做的事情”的入口，并把“已过期任务”视为应重设截止日期的未处理任务。[在滴答清单中实践 GTD](https://help.dida365.com/tasks/a/6427792882765135872/%E5%9C%A8%E6%BB%B4%E7%AD%94%E6%B8%85%E5%8D%95%E4%B8%AD%E5%AE%9E%E8%B7%B5%20GTD)
- **【官方已验证】** 月视图可以通过“显示已完成”开关决定已完成任务是否可见；关闭后用于只看遗漏且未完成的任务。[月视图：每月总结复盘](https://help.dida365.com/articles/6950640298334617600)、[Calendar View Options](https://help.ticktick.com/articles/7055782085826445312)
- **【官方已验证】** 日历只显示被纳入显示范围的清单；官方 FAQ 还说明，清单若设置“不在智能清单中显示”，任务也可能从智能清单隐藏。[常见问题](https://help.dida365.com/articles/6950670128287580160)
- **【截图已验证】** 用户截图中的“今天”页存在“已过期 / 今天”切换；“月视图”中历史完成项置灰，未完成项更亮。

### 2.2 完成与取消完成

- **【官方已验证】** 任务可通过列表左侧方框或提醒弹窗中的“完成”打勾。[快速开始](https://help.dida365.com/start/6194405595563425792)
- **【官方已验证】** “已完成”是独立智能清单；日历是否显示完成项由开关控制。[TickTick FAQ](https://help.ticktick.com/articles/7055792921664028672)、[Calendar View Options](https://help.ticktick.com/articles/7055782085826445312)
- **【官方已验证】** 官方协作通知设置明确存在“完成 / 取消完成了任务”两类事件，因此产品支持取消完成（恢复）这一状态转换。[团队如何协作](https://help.dida365.com/articles/6950652002518958080)
- **【待产品决策】** 官方公开文档没有说明：普通任务完成后是否立即从“今天”页消失、是否保留在原分组底部、取消完成后回到原排序位置还是列表顶部。

### 2.3 重复任务

- **【官方已验证】** 支持每天、每周、每月、每年、自定义；中文版还明确支持“每周工作日（周一到周五）”、法定工作日和自选多个日期。[设置重复任务](https://help.dida365.com/articles/6950660365923385344)
- **【官方已验证】** 常见重复默认无限；可按日期结束，或“按次数结束”，达到次数后不再创建。[设置重复任务](https://help.dida365.com/articles/6950660365923385344)
- **【官方已验证】** 入门文档明确：自定义“每三天”任务完成后，会自动创建三天后的任务并设置提醒。这是“完成一次后生成下一次”的直接证据。[如何设置重复任务](https://help.dida365.com/start/6194436212359430144/%E5%A6%82%E4%BD%95%E8%AE%BE%E7%BD%AE%E9%87%8D%E5%A4%8D%E4%BB%BB%E5%8A%A1%EF%BC%9F)
- **【官方已验证】** 日历可开启“显示未来重复周期”；但在前一周期未完成前，未来周期不能被操作。这表明“未来预览周期”与“可操作实例”不是同一概念。[Calendar View Options](https://help.ticktick.com/articles/7055782085826445312)、[常见问题](https://help.dida365.com/articles/6950670128287580160)
- **【官方已验证】** 到期重复按原计划日期推进；完成重复按上次实际完成日期推进。若月度任务原定 1 日、3 日才完成，到期重复仍以每月 1 日为后续日期；完成重复以后续实际完成日为基准。[设置重复任务](https://help.dida365.com/articles/6950660365923385344)
- **【官方已验证】** 修改某一个周期的日期和时间，可选择“仅此周期”。官方更新日志确认重复任务支持单个周期删除和时间修改。[设置重复任务](https://help.dida365.com/articles/6950660365923385344)、[更新日志](https://www.dida365.com/public/changelog/zh.html)
- **【官方已验证】** “跳过此周期 / 下个周期”用于当前周期无法完成、且不希望影响未来重复提醒的情况；它不是完成。[重复任务跳到下个周期](https://help.dida365.com/tips/6427425932780240896/%E9%87%8D%E5%A4%8D%E4%BB%BB%E5%8A%A1%E8%B7%B3%E5%88%B0%E4%B8%8B%E4%B8%AA%E5%91%A8%E6%9C%9F)、[常见问题](https://help.dida365.com/articles/6950670128287580160)
- **【待产品决策】** 官方公开帮助没有说明“按次数结束”中的次数是否包含首次实例、跳过周期是否消耗次数、取消完成是否回滚次数。
- **【待产品决策】** 官方资料只明确“仅此周期”修改与单周期删除能力，没有公开删除时是否同时提供“此周期及以后 / 整个系列”等选项，也没有说明删除单周期是否消耗重复次数。

### 2.4 提醒

- **【官方已验证】** 创建或编辑任务时可设置提醒；日期时间智能识别可同时生成日期、时间和准时提醒。[智能识别日期](https://help.dida365.com/tips/6427419485019308032/%E6%99%BA%E8%83%BD%E8%AF%86%E5%88%AB%E6%97%A5%E6%9C%9F)、[超强大的提醒功能](https://help.dida365.com/articles/6950660229746917376)
- **【官方已验证】** 提醒弹窗提供“忽略、开始专注、完成、稍后提醒”；锁屏和应用外也可提醒。[超强大的提醒功能](https://help.dida365.com/articles/6950660229746917376)
- **【官方已验证】** Android 若要更准时，需要开启“闹钟模式”；通知权限、自启动、待机后台运行与安全软件白名单会影响提醒。[超强大的提醒功能](https://help.dida365.com/articles/6950660229746917376)、[常见问题](https://help.dida365.com/articles/6950670128287580160)
- **【官方已验证】** 重复任务完成并创建下一周期时，下一周期会设置提醒；到期重复和完成重复决定下一提醒时间的计算基准。[如何设置重复任务](https://help.dida365.com/start/6194436212359430144/%E5%A6%82%E4%BD%95%E8%AE%BE%E7%BD%AE%E9%87%8D%E5%A4%8D%E4%BB%BB%E5%8A%A1%EF%BC%9F)、[设置重复任务](https://help.dida365.com/articles/6950660365923385344)
- **【待产品决策】** 官方没有公开：编辑时间后旧系统闹钟何时取消、完成/删除后待触发闹钟是否立即撤销、取消完成是否恢复旧提醒、设备重启后如何重建系统闹钟。

### 4.3 重复任务生成时机与前序门闩

#### 已验证的竞品行为

1. **【官方已验证】** 完成当前重复任务后，会自动创建下一次并设置提醒。
2. **【官方已验证】** 可以显示所有未来重复周期，但当前周期未处理前，未来周期不能操作。
3. **【官方已验证】** 跳过当前周期可推进到下一周期，同时不影响未来重复提醒。
4. **【官方已验证】** 单周期日期/时间修改和单周期删除均受支持。

这四点共同说明：界面上出现的“未来周期”可以是预测投影，不能据此断言数据库已预生成多个可编辑实例。官方没有公开其存储模型。

#### 本项目建议的生成模型

| 规则 | 本项目建议 | 理由 |
|---|---|---|
| 可操作实例 | 每个系列任一时刻只保留一个当前可操作实例 | 直接满足官方“前序未处理，未来不可操作” |
| 未来展示 | 按规则动态计算虚拟 occurrence，只用于月视图预览 | 避免提前物化造成重复、编辑系列难以收敛 |
| 下一实例生成 | 完成或跳过当前实例的服务端事务内生成 | 满足“完成一次自动生成下一次”；联网存储有唯一真值 |
| 幂等 | `(series_id, occurrence_key)` 唯一约束 | 防止弱网重试生成两个下一周期 |
| 每天 | 下一合法自然日 | 不以 24 小时毫秒相加，避免时区/夏令时问题 |
| 工作日 | 下一周一至周五 | 用户要求的是普通工作日；不自动引入法定节假日规则 |
| 每周指定星期 | 从规则集合中求严格晚于当前基准的最近星期 | 多星期必须稳定排序 |
| 每月指定日期 | 下一包含该日号的月份；缺失日如何处理 | 【待产品决策】建议“跳过无该日的月份”，不能声称竞品如此 |
| 指定次数 | 每生成/完成一个 occurrence 如何计数 | 【待产品决策】建议首次计 1、完成计数、跳过也消耗一次；UI 明示剩余次数 |
| 到期重复 | 从计划到期日推算下一次 | 对齐官方定义 |
| 完成重复 | 从实际完成时间推算下一次 | 对齐官方定义；首版若只做固定日历重复，可不暴露该高级选项 |

### 4.4 “完成 / 跳过 / 删除单次 / 删除系列”不能合并

| 动作 | 当前周期历史 | 是否记完成 | 系列是否继续 | 下一周期 | 证据状态 |
|---|---|---:|---:|---|---|
| 完成当前实例 | 保留完成记录 | 是 | 是 | 自动创建并设置提醒 | 【官方已验证】 |
| 跳过当前周期 | 应区别于完成；页面留痕方式未知 | 否 | 是 | 推进到下周期，不影响未来提醒 | 前半【待产品决策】；后半【官方已验证】 |
| 删除单周期 | 官方确认能力，历史留痕方式未知 | 否 | 是 | 系列继续，但次数语义未知 | 能力【官方已验证】；细节【待产品决策】 |
| 删除系列 | 官方未公开精确范围 | 否 | 否 | 不再产生未来周期 | 【待产品决策】 |

## 5. 提醒生命周期：已验证事实与本项目规则

| 事件 | 竞品已验证行为 | 证据状态 | 本项目建议规则 |
|---|---|---|---|
| 创建任务并设日期时间 | 可设置提醒；智能识别可生成准时提醒 | 【官方已验证】 | 服务端保存后客户端创建 exact alarm；无权限则明确降级 |
| 编辑到期/提醒时间 | 官方确认可修改日期、时间和提醒，但未公开旧闹钟处理 | 【待产品决策】 | 先取消旧 alarm identity，再按服务端最新版本安排新 alarm |
| 完成单次任务 | 可从提醒弹窗完成；旧提醒是否显式取消未公开 | 【待产品决策】 | 立即取消该实例所有未触发提醒 |
| 完成重复当前实例 | 下一周期会创建并设置提醒 | 【官方已验证】 | 取消当前实例提醒；仅为新可操作实例安排提醒 |
| 跳过当前周期 | 不影响未来重复提醒 | 【官方已验证】 | 取消当前实例提醒；安排下一实例提醒 |
| 删除任务/单周期/系列 | 官方未公开系统闹钟后果 | 【待产品决策】 | 删除范围内所有未触发提醒；系列删除同时取消系列键下所有 alarm |
| 取消完成 | 官方确认有该动作，提醒恢复语义未公开 | 【待产品决策】 | 若原提醒仍在未来则重建；若已过期则不补响，显示“提醒已过期” |
| 设备重启 | 官方只要求自启动、后台存活/白名单，未公开重建机制 | 【待产品决策】 | 接收 `BOOT_COMPLETED` 后从本地镜像重建未来提醒；联网后再与服务器校准 |
| 应用被系统限制 | 官方称会影响提醒，建议闹钟模式、自启动、后台运行和白名单 | 【官方已验证】 | 首次启用提醒时做荣耀专项引导与可诊断状态页 |

### 5.1 荣耀 200 / MagicOS 9.0 的产品含义

- **【官方已验证】** 滴答清单官方把华为/荣耀列为 Android 特殊适配相关机型，并明确要求允许自启动、待机后台运行，必要时加入安全软件白名单。[常见问题](https://help.dida365.com/articles/6950670128287580160)
- **【官方已验证】** 官方说明部分 Android 手机要开启“闹钟模式”才能更准时。[超强大的提醒功能](https://help.dida365.com/articles/6950660229746917376)
- **【待产品决策】** 官方资料没有给出 MagicOS 9.0 的逐屏设置路径。本项目不应伪造路径；应在目标真机上确认后写入交互稿和验收步骤。

## 6. ADAPT：竞品行为与项目采用建议（分栏）

| 主题 | 滴答清单官方可验证行为 | 本项目建议规则 | 差异/风险 |
|---|---|---|---|
| 今天 | 按今天到期日期筛选 | 今天未完成高亮；当天完成保留底部置灰 | “完成后留在今天”未由官方文档确认，是为复刻截图语义和易恢复做的选择 |
| 已过期 | 过去仍未处理的任务需重新安排 | 所有过去日期且未完成任务集中显示 | 全天任务与定时任务统一按自然日，不按当前分钟判逾期 |
| 月视图 | 可显示/隐藏已完成；可预览未来重复周期 | 默认显示完成项以匹配截图；菜单可关闭 | 未来周期为投影，不等同真实可编辑实例 |
| 恢复 | 存在取消完成事件 | 按原到期日重新归类；提醒仅在未来时恢复 | 竞品排序和旧提醒恢复未确认 |
| 单周期编辑 | 可选“仅此周期” | occurrence override | 应与“改系列”使用明确二次选择 |
| 删除单周期 | 官方更新日志确认支持 | 删除异常，系列继续 | 是否消耗次数必须由产品定稿 |
| 删除系列 | 未由官方资料确认 | 删除当前与未来，保留历史完成记录 | 必须在确认弹窗写明影响范围 |
| 下一周期 | 完成后自动创建；前序未处理时未来不可操作 | 服务端事务生成一个下一实例，未来预览动态计算 | 联网失败时要防重复并允许本地乐观状态回滚 |
| 精准提醒 | 闹钟模式 + Android 后台/自启动设置 | exact alarm + 重启重建 + 荣耀真机引导 | 系统仍可能限制；不能承诺绝对准点 |

## 7. 推荐的本项目状态机（不是竞品事实）

```text
DRAFT
  └─ save ─> ACTIVE

ACTIVE
  ├─ due date passes ─> ACTIVE_OVERDUE   （查询派生状态）
  ├─ edit date ───────> ACTIVE            （按新日期重新归类）
  ├─ complete ────────> COMPLETED
  ├─ skip recurrence ─> SKIPPED            （仅重复实例）
  └─ delete ──────────> DELETED

COMPLETED
  └─ uncomplete ──────> ACTIVE / ACTIVE_OVERDUE（由原到期日决定）

ACTIVE(recurrence)
  ├─ complete ─> COMPLETED + create next ACTIVE occurrence
  └─ skip ─────> SKIPPED   + create next ACTIVE occurrence
```

- `ACTIVE_OVERDUE` 建议为查询派生状态，不单独写入数据库，避免午夜批量改状态。
- `DELETED` / `SKIPPED` 建议保留服务端墓碑，避免多端虽非目标、但同设备离线重试导致“复活”。
- `COMPLETED` 必须保存 `completedAt`；重复系列还需保存计划 occurrence key，不能只改父任务的下次日期。

## 8. 尚未由官方资料确认的项目决策清单

以下均不得写进 PRD 为“滴答清单就是这样”，必须由产品确认：

1. 普通任务完成后在“今天”页是立即隐藏，还是留在底部置灰；本报告建议留在底部。
2. 取消完成后的排序位置，以及已过期提醒是否补响；建议按原到期日归类且不补响。
3. 删除普通任务是硬删除还是可恢复软删除；建议服务端软删除。
4. 删除重复系列的范围选项；建议至少提供“仅此周期 / 当前及以后（整个系列）”。
5. 修改重复规则的作用范围；建议仅改当前及未来，保留已完成历史。
6. “指定次数”是否包含首次、跳过/单周期删除是否消耗次数；建议首次计 1、跳过消耗、删除单次也消耗，但需用户确认。
7. 每月 29/30/31 遇到缺失日期时是跳过还是取月末；建议跳过该月，但需用户确认。
8. 完成后再取消完成，是否删除已经生成的下一周期；建议禁止造成两个可操作实例，需设计冲突处理。
9. 设备重启、应用升级、时区变化后的提醒重建策略；竞品未公开，本项目须自行定义和测试。
10. MagicOS 9.0 的精确授权路径；需荣耀 200 真机验证。

## 9. 对抗性核验与证据限制

1. “月历已显示未来重复任务”不等于“数据库预生成全部实例”。官方同时明确未来周期在前序未处理前不可操作，因此报告将其解释为可预览 occurrence，而非存储事实。
2. 官方英文重复帮助的 FAQ 有一处标题/正文疑似翻译错配，把“到期重复 vs 完成重复”的示例写在另一结束条件标题下；本报告采用中文官方页的完整定义，不沿用错误标题。
3. “取消完成”只能由官方通知选项证明动作存在，不能证明取消完成后的列表排序或提醒恢复。
4. 官方更新日志证明“单周期删除”能力，但没有证明删除弹窗包含哪些系列范围选项。
5. 官方 Android 提醒文档证明权限和后台限制会影响准时性，但没有公开 AlarmManager、重启广播等内部实现；本报告的重建方案是项目建议。
